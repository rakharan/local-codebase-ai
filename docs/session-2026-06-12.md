### Fix: BM25 Disk Cache ✅

The BM25 in-memory index was rebuilt from scratch on every process start (scrolling 152k Qdrant points, ~17s). Added disk cache at `.data/bm25-index.json`.

**Behavior:**
- First build: ~17s, saves to disk
- Subsequent starts: ~1s (load from disk)
- Cache invalidation: 6h TTL or >1% point count change
- Only indexes 52k/152k chunks (identifier-rich: symbols, tables, routes, queues)
- Uses separate `QdrantClient` instance to avoid ECONNRESET with main query client

**Fix: `MiniSearch.loadJSON` cast** — CJS build doesn't expose `loadJSON` as a typed static method; added `as unknown` cast.

**Commits:** `6267f64`, `badedf2`

---

### Fix: BM25 ECONNRESET ✅

Concurrent BM25 scroll and vector search were sharing the same Qdrant connection pool, causing ECONNRESET on vector search. Fixed by using a dedicated `bm25QdrantClient` in `bm25-index.ts`.

Also added graceful degradation: all `qdrant.retrieve()` BM25 calls in `ask.ts` now catch ECONNRESET and skip BM25 boost rather than crashing.
