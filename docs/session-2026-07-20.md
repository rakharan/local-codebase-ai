#### P0 — Reliability (no more silent failures)

- **qdrant.ts** — `ensurePayloadIndexes` catch narrowed to 409 / `already exists`. Connection, schema, auth, and server errors now propagate so startup fails loudly instead of running unindexed.
- **bm25-index.ts** — `saveToDisk` and `loadCached` failures now logged (`[bm25]` prefix). Previously a broken disk cache forced a ~60s cold rebuild on every restart with no signal.
- **ask.ts** — BM25 payload retrieval failure (`retrieve()`) now sets a `retrievalDegradation.bm25Unavailable` flag and emits a structured JSON log (`event: bm25_payload_unavailable`). The flag is reset per query in `main()` and surfaced in the answer output as `[degraded] keyword (BM25) search was unavailable`.
- **ask.ts** — Replaced `chat(decisionPrompt).catch(() => "")` with try/catch distinguishing LLM-call-failure from empty response. Failure is logged (`event: llm_call_failed`) and the degrade-to-general-retrieval path is recorded (`event: degrade_to_general_retrieval`).
- **server.ts** — Added `/api/ready` readiness probe: cached (5s) Qdrant `getCollections` + Ollama `/api/tags` checks, returns 503 when degraded. `/api/health` stays as liveness-only.

#### P1 — Operational risk

- **bm25-index.ts** — In-process TTL now configurable (`BM25_INDEX_TTL_MS`, default 60m, was 10m) + point-count fast-path: when TTL elapses, if Qdrant point count is unchanged, the in-memory index is kept and the disk JSON reload is skipped. Diagnostics log cache load / cold-build / fast-path decisions.
- **ask.ts + qdrant.ts** — `evidenceTypes` added to `PAYLOAD_INDEXES`. `retrieveDocumentationSubjectMatches` and `retrieveExactVocabularyMatches` now push the `evidenceTypes=documentation` filter server-side, narrowing the ~152k-point scroll to the documentation subset instead of filtering client-side.
- **index-repo.ts** — Sequential `await`-per-chunk embed+upsert loops replaced with `mapWithConcurrency` (`config.indexConcurrency`, env `INDEX_CONCURRENCY`, default 4). Applies to both code-chunk and commit-chunk loops; preserves order, fail-fast.
- **scripts/reindex-all.ts** (new) — Lock-protected wrapper: `doctor-all` → `index-doctor-all`. Uses `.data/reindex.lock` (exclusive create + stale-lock steal after 4h). Lock releases on failure via `finally`. `npm run reindex-all`. Verified lock acquire / release-on-failure / abort-when-held.
